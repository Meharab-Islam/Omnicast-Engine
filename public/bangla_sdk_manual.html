লাইভ মিডিয়া সার্ভার SDK ইন্টিগ্রেশন ম্যানুয়াল

আমাদের Go (Fiber + Pion WebRTC + Redis) ভিত্তিক আল্ট্রা-হাই পারফরম্যান্স লাইভ মিডিয়া সার্ভারের সম্পূর্ণ আর্কিটেকচারাল এবং ক্লায়েন্ট SDK ইন্টিগ্রেশন গাইড। এই ম্যানুয়ালটি যেকোনো প্ল্যাটফর্মে (Flutter, React Native, iOS, Android) সম্পূর্ণ নির্ভরযোগ্য এবং ল্যাগ-মুক্ত SDK তৈরির জন্য প্রস্তুত করা হয়েছে।

১

সিস্টেম আর্কিটেকচার (SFU Cascading & Ultra-Optimization)

আমাদের লাইভ মিডিয়া সার্ভারটি কোনো সাধারণ মনোলিথিক ওয়েব সার্ভার নয়; এটি লক্ষ লক্ষ কনকারেন্ট ব্যবহারকারীকে মিলি-সেকেন্ড লেটেন্সিতে সেবা দেওয়ার জন্য ৪টি মূল পারফরম্যান্স পিলারের ওপর নির্মিত:

🚀 Zero-Allocation Memory Pooling

প্রতিটি ভিডিও ফ্রেমে নতুন মেমোরি অ্যালোকেশন এড়াতে Go-এর sync.Pool ব্যবহার করা হয়েছে। 1500-byte MTU RTP বাফার পুনঃব্যবহারের মাধ্যমে গারবেজ কালেক্টর (GC Pause) চাপ শূন্যের কোঠায় নামিয়ে আনা হয়েছে।

⚡ Goroutine Worker Pool

প্রতিটি ভিউয়ারের জন্য পৃথক গোরুটিন না তৈরি করে একটি কেন্দ্রীয় 64-ওয়ার্কার বাউন্ডেড পুলের মাধ্যমে মেসেজ ও RTP প্যাকেট ফ্যান-আউট করা হয়। ফলে মেমোরি ও CPU থ্রেড ওভারহেড বাঁচে।

🌐 SFU Cascading (Origin-Edge)

হোস্ট যেখানেই থাকুক না কেন, ভিডিও স্ট্রিম ব্যাকবোন নেটওয়ার্ক দিয়ে এজ সার্ভারে ক্যাসকেডিং হয়। ফলে কোটি ভিউয়ারের ক্ষেত্রেও হোস্টের আপলোড ব্যান্ডউইথ মাত্র একটি স্ট্রিমের সমান (1.2 Mbps) থাকে।

🔄 Redis Pipeline Batching

প্রতিটি গিফট বা লাইভ ইভেন্টে সাথে সাথে ডাটাবেজে হিট না করে RAM-এ ডেল্টা স্কোর জমা করে প্রতি ২ সেকেন্ড পর পর Redis Pipeline (INCRBY) দিয়ে ব্যাচ আপডেট করা হয়।

মোবাইল নেটওয়ার্কে TURN সার্ভার কেন অপরিহার্য?

সমস্যাটি কী?

লাইভ শুরু হওয়ার ৩০ মিনিট পর যখন কোনো দর্শক রুমে প্রবেশ করে, তখন সে অতীতের লাইভ চ্যাট বা ইভেন্টগুলো মিস করে। কার কত স্কোর, ৮টি সিটের মধ্যে কোনটায় কে বসে আছে এবং কার ক্যামেরা মিউট—তা দর্শক জানতে পারে না।

🚨
মাস্টার রুল: Offer তৈরির আগেই Transceiver যুক্ত করতে হবে!
WebRTC স্পেসিফিকেশন অনুযায়ী, createOffer() কল করার আগেই addTransceiver দিয়ে ভিডিও এবং অডিও ট্র্যাক যুক্ত করতে হবে। অন্যথায় SDP Offer-এ মিডিয়া সেকশন (m=video) তৈরি হবে না এবং সিমুলকাস্ট এনকোডিং লেয়ার (f, h, q) নিষ্ক্রিয় হয়ে যাবে।

    { rid: 'h', active: true, maxBitrate: 500000, scaleResolutionDownBy: 2 },// Medium (480p)
    { rid: 'q', active: true, maxBitrate: 150000, scaleResolutionDownBy: 4 } // Low (240p)
  ]
});

// ২. এরপর Offer তৈরি করো:
const offer = await peerConnection.createOffer();

// ৩. Local Description সেট করে সার্ভারে পাঠাও:
await peerConnection.setLocalDescription(offer);

ক্লায়েন্ট SDK স্ট্রাকচার (Flutter / React Native Guide)

যেকোনো মোবাইল বা ওয়েব ক্লায়েন্টে সহজে ইন্টিগ্রেশনের জন্য আপনার অ্যাপকে ৪টি প্রধান মডিউলে বিভক্ত করুন:

1. LiveAuthClient

REST API হ্যান্ডেল করে এবং JWT টোকেন ও ডাইনামিক Coturn ICE সার্ভার ক্যাশ করে রাখে।

2. LiveSignalingClient

WebSocket কানেকশন, হার্টবিট পিং/পং এবং অটো-রিকানেক্ট হ্যান্ডেল করে।

3. LiveMediaEngine

flutter_webrtc রেন্ডারার, ৩-লেয়ার সিমুলকাস্ট এবং ডাইনামিক SDP রিনেগোশিয়েশন নিয়ন্ত্রণ করে।

4. LiveRoomState

ChangeNotifier/ValueNotifier ভিত্তিক রিঅ্যাক্টিভ স্টোর যা ডায়মন্ড স্কোর ও সিট লাইভ আপডেট করে।
